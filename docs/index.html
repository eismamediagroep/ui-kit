Eisma UI Kit

Framework-agnostic Web Components built on Alpine.js and Tailwind v4.

Installation

Via CDN — zero install, paste a script tag:

<script src="https://cdn.jsdelivr.net/gh/eismamediagroep/ui-kit@main/dist/eisma.iife.js" defer></script>

Pin a tag (@v0.1.0) for production or use @main while iterating.

Via npm — published to GitHub Packages:

npm install @eismamediagroep/ui-kit

Page setup — load Alpine and the bundle. Alpine handles all reactivity; the bundle registers the custom elements.

<script src="https://unpkg.com/alpinejs@3.x" defer></script> <script src="https://cdn.jsdelivr.net/gh/eismamediagroep/ui-kit@main/dist/eisma.iife.js" defer></script>

Tailwind setup

Build pipeline: add the package to your Tailwind input CSS so utility classes are scanned:

@import "tailwindcss"; @source "../node_modules/@eisma/ui-kit/dist/**/*.js";

Browser CDN: use the v4 browser bundle. Do not use the old cdn.tailwindcss.com (v3 Play CDN) — its runtime scanner doesn't reliably pick up classes added by custom elements after their initial mount.

<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

Dark mode

Components ship with dark: variants. Activate class-based dark mode by adding this to your CSS:

@custom-variant dark (&:where(.dark, .dark *));

Then drop in <eisma-theme-toggle> for a persistent toggle with system-preference fallback, or toggle class="dark" on <html> yourself.

To prevent a light flash on load, add this inline in <head>:

<script> var stored = localStorage.getItem('eisma-theme'); var dark = stored === 'dark' || (!stored && matchMedia('(prefers-color-scheme: dark)').matches); document.documentElement.classList.toggle('dark', dark); </script>

Color tokens

The primary, secondary, and link button variants pull from Tailwind v4 @theme tokens — set the brand once and every button picks it up.

inline { --color-primary: #183E74; --color-primary-foreground: rgb(255 255 255 / 0.95); --color-secondary: #F6A600; --color-secondary-foreground: rgb(20 20 20 / 0.9); }

Programmatic control

Give the tooltip an id and you can drive it from anywhere via Alpine $dispatch. The eisma-tooltip-flash event shows a temporary message and reverts — perfect for "copied!" feedback.

hello@example.com
<eisma-tooltip id="copy-email" text="Copy email"> <eisma-button icon-left="copy" x-data x-on:click=" navigator.clipboard.writeText('hello@example.com'); $dispatch('eisma-tooltip-flash', { id: 'copy-email', text: 'Copied!' }); " > hello@example.com </eisma-button> </eisma-tooltip>

Events

EventDetail
eisma-tooltip-show{ id, text? } — open; optionally swap text
eisma-tooltip-hide{ id } — close
eisma-tooltip-toggle{ id, text? } — toggle; optionally swap text
eisma-tooltip-flash{ id, text, duration? } — temporarily show text, revert (1500ms default)

Accordion

Single-open by default. Add type="multiple" on <eisma-accordion> to allow multiple items open at once.

Is it accessible? Yes. Triggers are buttons with aria-expanded; content is wrapped in role="region" with an id the trigger references via aria-controls. Is it styled? Yes. Triggers use the same font/size conventions as the rest of the kit; items get a thin neutral divider between them. Can multiple items be open? Set type="multiple" on the accordion. Each item then manages its own open state independently.
<eisma-accordion> <eisma-accordion-item value="q1"> <eisma-accordion-trigger>Is it accessible?</eisma-accordion-trigger> <eisma-accordion-content> Yes… </eisma-accordion-content> </eisma-accordion-item> </eisma-accordion>

Icon

Lazy-loads from lucide, heroicons, or FontAwesome on first use and caches in memory. Inherits color via currentColor.

<!-- lucide (default) --> <eisma-icon name="search"></eisma-icon> <!-- heroicons --> <eisma-icon library="heroicons-solid" name="star"></eisma-icon> <!-- fontawesome brands / solid / regular --> <eisma-icon library="fa-brands" name="github"></eisma-icon> <eisma-icon library="fa-brands" name="linkedin" class="text-[#0a66c2]"></eisma-icon> <eisma-icon library="fa-solid" name="heart" class="text-red-500"></eisma-icon>

Available libraries: lucide · heroicons (outline) · heroicons-solid · heroicons-mini · fa-brands · fa-solid · fa-regular.

Custom / brand icons

Two paths for icons that aren't in any of the bundled libraries: src (any URL — fetched + cached) or paste an inline <svg> as a child. Existing fills in the SVG are preserved either way, so brand colors come through.

<!-- fetch from any URL --> <eisma-icon src="/assets/eisma.svg" size="40"></eisma-icon> <!-- or paste the SVG inline --> <eisma-icon size="32"> <svg xmlns="..." viewBox="0 0 43 43"> <path d="..." style="fill:#163e74"/> <path d="..." style="fill:#f7a600"/> </svg> </eisma-icon>
